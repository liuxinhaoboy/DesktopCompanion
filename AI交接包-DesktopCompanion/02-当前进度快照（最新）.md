### 关键设计
- **非模态**：SettingsPanel 是 QWidget + show()，绝不用 QDialog.exec()——exec 会冻住 qasync 让桌宠停止呼吸；所有确认框同理只用 show()+信号
- **密钥"留空=不修改"**：on_save 里密钥框为空就不把该字段放进结果 dict，避免用户只改个模型名保存却把已存密钥抹掉（P3 最危险的坑，有专门测试守住）
- **三段密钥统一加密**：apply_config 把 llm.api_key / vision.api_key / voice.stt_api_key 里用户新填的明文一律走 SecretsManager 加密成 secret: 引用，config.json 不出现任何明文
- **视觉模型联动**：未启用视觉时整段锁定；启用但勾"继承文本API"时独立地址/密钥仍锁定，取消继承才可填
- **导入角色校验**：抽成静态方法 validate_character_folder（无 manifest / 坏 JSON / 缺 id·name / id 含 \/:*?"<>| / 缺 system_prompt 全部拦截）；copytree 复制不动原文件夹，同 id 已存在则拒绝（防止两角色共用数据目录导致记忆互串）
- **选 PNG 立绘**：CharacterManager.set_avatar() 把图片复制进角色目录成 avatar.png、原子更新 manifest.avatar、重载该 profile；AppController 对当前伙伴立即 pet.apply_character() 热换外观（底层 PetRenderer 的 PNG 绘制/坏图回退矢量在更早版本已就绪，本次补齐 UI 与接线）

- **深色模式适配**：Windows 深色主题下 Qt 默认黑底白字，STYLE 把 QWidget/QTabWidget/QScrollArea/QGroupBox 背景与文字颜色全部写死成暖白，否则界面发黑看不清（离屏截图已逐页核对）

## 五·十二、本次接手修复的两个真实 bug

1. **关闭设置面板会连带退出整个桌宠**（P3 遗留）
   - 根因：Qt 默认 quitOnLastWindowClosed=True，而宠物窗口是 Tool 类型（无任务栏图标），Qt 不把它算进"应用窗口"计数 → 设置面板一关就被判定"窗口全关了" → 整个应用退出
   - 修复：AppController.configure_app_lifecycle() 里 setQuitOnLastWindowClosed(False)；桌宠是常驻应用，退出只有右键「让她下班」一条路
   - 守护：test_settings.py 的 test_app_lifecycle_disables_quit_on_last_window。**用变异验证确认有效**（把修复 monkeypatch 掉，测试确实抛 AssertionError，不是空过）
   - ⚠️ 曾写过一条"关面板后宠物还活着"的行为测试，变异验证证明它**抓不到 bug**（离屏环境 close() 不触发真实 lastWindowClosed→quit 流程），已删除，避免虚假安全感

2. **导入角色文件夹漏查 lines.json**（本次发现并修复）
   - 根因：设置面板的 validate_character_folder 只查 manifest + system_prompt，**漏查 lines.json**；而运行时 load_character 强制要求 lines.json，缺了会抛错 → list_characters 静默跳过该角色
   - 后果：用户导入一个缺 lines.json 的文件夹会提示"导入成功"，可角色列表里根本没有它，小白完全不知道发生了什么
   - 修复：validate_character_folder 补上 lines.json 检查（缺失/坏 JSON/一句有效台词都没有 都拦下），与 loader.validate_dir 保持一致
   - 守护：test_settings.py 新增 3 条（test_import_rejects_missing_lines / _empty_lines / _broken_lines_json）

## 七、已踩过的坑（别重踩）

- `QFontMetrics.boundingRect` 只收整数 QRect，QRectF 直接 TypeError
- `QWidget.screen()` 返回方法对象，用 `QApplication.primaryScreen()`
- Windows深色模式 QTextEdit 默认白字，浅色背景必须 stylesheet 写死 color
- docode.cc 返回开头带 `\u200b` 零宽空格，sanitize() 清除
- temperature 夹在 [0.6, 1.1]（gpt-5系对>1敏感）
- 情绪衰减有下限20（time_decay_floor），否则放一晚暴怒常驻捣乱倍率7.5
- 模块单独跑必须 `python -m soul.engine`，不能 `python soul/engine.py`
- ChromaDB 初始化慢（首次约5-10秒），测试跑起来耐心等
- **测试中 QApplication 实例必须存全局变量**：`_make_qapp()` 返回值若不保持引用，Python GC 会回收 QApplication，导致后续 QWidget 创建时报 "Must construct a QApplication before a QWidget" 并以 0xC0000409 原生崩溃，且无 Python traceback
- DPAPI 加密用 pywin32 的 win32crypt.CryptProtectData/CryptUnprotectData，密文绑定 Windows 用户

### 关键设计

- **为什么用 CESM 事件监听赚币**：CESM 是唯一事件入口，挂别处迟早漏路径。
  监听器在**锁外**回调，且异常被吞掉——经济系统绝不能影响情绪系统。
- **为什么零食用 boost 倍数而不是写死 hunger 数值**：写死等于把 CESM 的加成公式
  抄一份到商品表，公式一改两边就对不上。
- **不做惩罚性通胀**：捣乱被拒、被冷落都不扣币。币只增不减（除消费）。
- **钱包跟着角色走**：换角色会重建 CESM，`_rebind_economy()` 必须重挂，
  否则新角色的陪伴行为不再产生币（已实测：小蓝 90 币 / 豆豆 0 币，各自独立）。
