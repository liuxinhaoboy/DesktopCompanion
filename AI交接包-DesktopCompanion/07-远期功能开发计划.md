## A. 昼夜作息（预计 1 个对话内完成）

**目标**：把"深夜静默"升级成完整的作息系统——她有晨昏节律，夜里真在睡觉（视觉+文案+数值），
白天活动度随时间变化，用户熬夜她会吐槽。

**现状代码事实**：
- `brain/decide.py` L57 已从矩阵读 `作息.quiet_hours`（23 点与 0-6 点），L95 命中就
  `return None` 静默——这是唯一实现了的"作息"。
- `brain/chaos_trigger_matrix.json` 的 `作息` 段只有 quiet_hours 一个字段。
- `config.json` 的 `sleep` 段（`sleep_enabled/sleep_start_hour/sleep_end_hour/...`）
  **没有任何代码读取，是死配置**（上轮已核实）。
- 渲染器（`face/pet_renderer.py`）没有睡觉视觉；宠物窗口 `say()` 可冒气泡。
- `soul/engine.py` 的 PSE 衰减是全天匀速的，没有昼夜系数。

**设计**：
1. **配置统一**：删除 `config.store.DEFAULT_CONFIG` 里的 `sleep` 段（避免双源头），
   作息全部收进 `chaos_trigger_matrix.json` 的 `作息` 段，新增：
   `wake_hours:[7..22] 内按小时的活动系数`（如凌晨 6 点 0.4、正午 1.0、晚上 21 点 0.7）、
   `greet_morning/greet_night` 台词触发时段。
2. **Decider 升级**：`decide.py` 的静默判断从"小时 in quiet_hours"扩展为查系数表，
   捣乱概率 × 时段系数；深夜返回特殊标记 `SLEEPING` 而不是 None，供 UI 显示睡眠态。
3. **睡眠视觉**：`pet_window.py` 加 `set_sleeping(bool)`：闭眼常驻 + 呼吸频率减半
   （改 `_breath_timer.interval`）+ 每 90 秒冒一个 Zzz 气泡（项目当前没有任何 Zzz 元素，
   这是新增）。`face/pet_renderer.py` 三套渲染路径（矢量/立绘/3D）都要支持 sleeping 参数
   ——矢量画闭眼、立绘用现成 sleep 帧、3D 调暗（复用现有 dim 系数）。
4. **PSE 联动**：`soul/engine.py` 饥饿/情绪衰减乘时段系数（睡觉时衰减减半）；
   用户在 quiet_hours 主动聊天不阻止，但她回复带"唔…好困"前缀（engine 拼一句台词）。
5. **早安/晚安**：启动时若处于 wake 边界 ±1 小时，`greet()` 换对应台词
   （`pet_window.py` L128 的 greet 已是单点入口，好挂）。

**实现步骤（文件级）**：
1. `brain/chaos_trigger_matrix.json`：扩展 `作息` 段（保持旧字段兼容，缺系数表=全天 1.0）
2. `brain/decide.py`：读系数表；`decide()` 返回值语义扩展（None 与 SLEEPING 区分）
3. `brain/loop.py`：透传 SLEEPING 状态给 `AppController`
4. `face/pet_window.py`：`set_sleeping()` + Zzz 气泡定时器 + 启动问候分支
5. `face/pet_renderer.py`：paint 签名加 `sleeping: bool = False`（三路径都处理）
6. `soul/engine.py`：衰减乘时段系数 + 困倦前缀台词
7. `config/store.py`：删 DEFAULT_CONFIG 的 sleep 段；同步 config_template.json、config_schema.json
8. 测试：`tests/test_circadian.py`——系数解析与兼容（缺表=1.0）、SLEEPING 判定边界
   （22:59/23:00）、renderer sleeping 参数三路径不崩、engine 夜间衰减半、
   旧 config 文件删段后 load 不报错

**验收**：把系统时间改到凌晨（或 monkeypatch `per.hour`）跑集成脚本，确认：无捣乱事件、
眼睛闭着、有 Zzz、聊天带困倦前缀；改回白天一切如旧。九套回归 + 冒烟全绿。

**风险与回滚**：decide 返回值语义变更影响 loop 消费方，改前先 grep `decide(` 的全部调用点；
若用户反馈睡觉视觉"像卡死"（和假死 L2 撞车），sleeping 与 `_frozen` 必须可区分
（假死有抱怨气泡，睡觉有 Zzz，视觉上给 Zzz 加专属色）。

## B. 商城经济（预计 1-2 个对话）

**目标**：本地单机的虚拟货币闭环：陪伴行为赚币 → 商店买零食/配饰/台词包 → 戴上的配饰
渲染可见、买的零食喂食更香。**绝不涉及真实货币、内购、联网支付。**

**现状代码事实**：
- `soul/engine.py` 的 state 已有 `counters`（total_chats/total_feeds/chaos_done 等）和
  `affinity/trust/mood/hunger` 四数值，喂食 `feed()` 已存在且支持 meal_types——经济系统
  是给它加"钱"，不是从零建。
- state.json 每角色独立（`data/characters/<id>/state.json`），损坏有自动备份重建机制，
  加字段要走同一套"旧文件补默认值"逻辑（参考 hunger 字段的先例，test_pse 有
  `test_old_state_file_gets_default_hunger` 可抄）。
- 设置面板是六标签页（`face/settings_panel.py`），加"商店"入口的位置在宠物页或新增第七页。
- 渲染器叠加配饰：矢量路径在 paint 最后叠画即可；立绘/3D 角色配饰用「锚点贴图」方案
  （帽子画在头顶固定比例位置），两种渲染路径共用一个 accessory overlay 函数。

**设计**：
1. **货币**：`state` 加 `coins`（整数）。获取：每日首聊 +5、喂食成功 +2、陪她完成
   L1 捣乱（她得逞）+1、连续 3 天有互动每日递增 +1/+2/+3；上限防刷：单日赚取封顶 30。
2. **商品表**：新增 `shop/catalog.json`——零食（比默认喂食 mood/hunger 加成更高、有
   限定款）、配饰（帽子/围巾/蝴蝶结，画在头顶/脖子）、台词包（买后对应 lines 场景生效）。
   每件：id/名称/价格/类型/效果参数/图标（复用矢量小画，不必外部图片）。
3. **商店 UI**：设置页新增第七标签「商店」：余额、分类列表、买/戴/吃按钮、已拥有置灰。
   沿用面板现成的非阻塞交互与 `_flash` 提示风格。
4. **拥有与装备**：`state` 加 `owned: [id...]` 与 `equipped: {head: id, neck: id}`；
   购买幂等（重复 id 拒绝）；配饰热更新走现有 `apply_character` 之后加
   `apply_accessories()` 刷新路径。
5. **经济不做惩罚性通胀**：所有已赚 coins 不因捣乱被拒而扣，红线是"她不能花用户的钱"——
   coins 只能由陪伴行为产生。

**实现步骤（文件级）**：
1. `soul/engine.py`：coins/owned/equipped 字段 + 旧 state 兼容 + 赚取规则挂现有事件点
   （chat/feed/chaos 回调处）+ `spend()`/`purchase()`/`equip()` 方法（全部本地事务）
2. `shop/catalog.json` + `shop/__init__.py`（加载校验：字段缺失跳过该商品并打日志，
   风格照抄 character_loader 的容错）
3. `face/settings_panel.py`：第七标签页（注意该文件有 Edit 权限坑，用就地覆写补丁）
4. `face/pet_renderer.py`：accessory overlay（head/neck 锚点比例常量集中定义）
5. `face/pet_window.py`：气泡旁显示 equipped 配饰的渲染刷新入口
6. `app/controller.py`：商店购买动作的 engine↔UI 中转（保持 UI 不直接碰 engine）
7. 测试：`tests/test_shop.py`——赚取封顶、购买扣币幂等、余额不足拒绝、旧 state 补字段、
   catalog 坏条目跳过不崩、equipped 不存在的 id 渲染回退无配饰
8. 冒烟 + 手工：买帽子→重启→还戴着（持久化）；换角色→配饰跟着角色数据走（隔离）

**验收**：上述测试全绿；真实程序里从聊天赚钱→买零食喂她→hunger/mood 增益高于默认喂食。

**风险**：数值失衡（太肝或太送）——首版定价宁可宽松，catalog.json 全部数值可调不需改码；
第七标签页会撑大 settings_panel（已 50KB），把商店页控件拆成 `face/shop_tab.py` 面板文件
导入组装，避免继续膨胀。

## C. 物理引擎（预计 1 个对话）

**目标**：拖动甩出去有惯性、落下有重力、碰屏幕边缘会弹、最后滚到桌面底部停下。
默认开启但**可一键关闭**（有人就爱钉在原地）。

**现状代码事实**：
- `face/pet_window.py` L217-226：鼠标按下只记 `_drag_offset`，移动直接 `move()`，
  松开什么都不做——完全没有速度概念。
- L120 `_move_to_start`：启动落位右下角（可作为"地面"定义参考：屏幕 availableGeometry 底边）。
- ACL `cover_window`（L188）也会 `self.move()` 程序性挪位——物理模块必须区分
  "用户抛掷"与"程序瞬移"，否则她盖窗口时会从窗口上掉下来滚走，观感灾难。
- 已有 50ms 呼吸 timer（L70），物理 tick 可直接搭同一 timer（20fps 对桌面尺度够用）。

**设计**：
1. 新文件 `face/physics.py`：纯 Python 向量小类（位置/速度/重力 1800 px/s²、
   恢复系数 0.35、地面摩擦衰减、屏幕边界碰撞反弹，全部常量集中可调、带中文注释）。
   `step(dt)` 返回新位置，无 Qt 依赖、可单测。
2. `pet_window.py`：
   - mouseMove 期间记录最近 5 个采样点（含时间戳），mouseRelease 用首尾差算初速度
   - 有初速度 → 启动物理模拟 timer；无（普通放下）→ 行为与现在完全一致
   - `set_programmatic_move(x, y)`：ACL 的 cover_window、_move_to_start 改走这里，
     内部**清零速度并暂停模拟**（抛掷/瞬移分离）
   - 模拟中再次按下鼠标立即接管（打断模拟）
3. 配置：`pet.physics_enabled`（默认 true）+ `pet.gravity_strength`（0.5~2 档）；
   设置面板宠物页加开关（该文件走就地覆写补丁）。
4. 观感细节：落地时播一下落地 squash（renderer 已有 size 缩放参数可用）、
   高速移动时轻微倾斜（phase 已有，加 tilt 可选，先不做）。

**测试**：`tests/test_physics.py`（纯逻辑无窗口）：step 能量单调不增、边界反弹速度方向、
摩擦后静止收敛、抛掷参数→轨迹可复现；窗口层集成脚本：mock 释放速度 → 数秒后位置
收敛到底边、`set_programmatic_move` 期间 timer 不推进模拟。

**验收**：回归全绿 + 冒烟；真机手动甩一下（这条只能人工，写进手工清单）。

**风险**：多显示器/负坐标——只允许在 primaryScreen 的 availableGeometry 内活动，出界
直接吸附边界；与 20fps timer 共用的呼吸动画不能被物理逻辑拖慢（step 必须 O(1)）。

## D. 隐藏彩蛋（预计 1 个对话，最后做）

**目标**：`hidden/`（现为空占位目录）落地一批只在被发现时才存在的玩法。**README 与设置
面板永远不提及它们**（对外口径不变，这本身就是彩蛋的一部分）。

**候选清单**（实现顺序自上而下，做完一个勾一个）：
1. **连续投喂 7 次**：她打嗝，吐出一枚稀有配饰（联动 B 的 owned 系统，走 `grant()`
   专用接口，来源标注 hidden，商店里看不到这件）。
2. **Konami 指令**：聊天框输入 `上上下下左右左右BA`（文本版更可靠，不监听全局按键）→
   她换 retro 配色 10 分钟。
3. **凌晨 3:33 精确对时启动**：开场白变成完全不同的"守夜人"文案（改 engine.greet_line
   的一个分支），并在 counters 记一次 `night_watch`。
4. **对她的名字好奇**：连续 3 天聊天里问她叫什么，第 3 天她会讲一段真名故事
   （写进角色包 `secret_lines.json`，缺失该文件的角色自动跳过此彩蛋）。
5. **物理彩蛋**：C 完成后，把宠物甩出屏幕底边瞬间她会"抓回来"并吐槽（利用物理越界事件）。

**设计约束**：
- 每个彩蛋独立开关式函数放 `hidden/eggs.py`，由 engine 已有事件点（chat/feed/启动/物理）
  广播触发，**不新增对主流程的侵入**；彩蛋失败静默跳过。
- 彩蛋状态记在 state 的 `hidden_progress`（旧文件补默认 `{}`）。
- 台词不进 lines.json 主结构，进独立 `secret_lines.json`（loader 缺失不报错）。
- 测试 `tests/test_hidden.py`：触发条件精确（第 6 次投喂不触发第 7 次的）、
  无 secret_lines 角色不崩、重启后 progress 持久、所有彩蛋对普通聊天路径零副作用
  （跑全套既有测试确认无任何断言被彩蛋扰动）。
